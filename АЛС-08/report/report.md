# Цель работы

Приобретение практических навыков по настройке динамического распределения IP-адресов посредством протокола DHCP (Dynamic Host Configuration Protocol) в локальной сети.

В существующую топологию был добавлен сервер **Server-PT** с именем **dns-arsenio**. Сервер был подключён к коммутатору **msk-donskaya-arsenio-sw-3** через порт **Fa0/2**. # Контрольные вопросы

1. За что отвечает протокол DHCP?

   **DHCP** — это сетевой протокол динамической настройки узлов, который автоматически выдаёт устройствам параметры IP-конфигурации. Его основная задача заключается в том, чтобы избавить администратора от ручной настройки IP-адресов на каждом компьютере, сервере, телефоне, принтере или другом сетевом устройстве.

   DHCP-сервер назначает клиенту IP-адрес из заранее настроенного диапазона адресов, который называется **пулом адресов**. Кроме самого IP-адреса, клиент обычно получает маску подсети, адрес шлюза по умолчанию, адрес DNS-сервера и дополнительные сетевые параметры.

   Протокол DHCP особенно важен в крупных сетях, где используется большое количество оконечных устройств. Если IP-адреса задавать вручную, возрастает риск ошибок: можно случайно указать неверную маску, неправильный шлюз или назначить двум устройствам один и тот же адрес. DHCP снижает вероятность таких ошибок и упрощает администрирование сети.

   В DHCP адрес выдаётся не навсегда, а на определённое время, которое называется **сроком аренды**. Пока срок аренды действует, клиент может использовать полученный адрес. Перед окончанием аренды устройство пытается продлить её, чтобы сохранить текущую конфигурацию. Если устройство отключается от сети и больше не использует адрес, DHCP-сервер может позднее выдать этот адрес другому клиенту.

2. Какие типы DHCP-сообщений передаются по сети?

   При получении IP-адреса по DHCP обычно используется последовательность сообщений, которую часто называют схемой **DORA**: **Discover**, **Offer**, **Request**, **Acknowledgement**.

   **DHCP Discover** — это начальное широковещательное сообщение клиента. Клиент отправляет его, когда ещё не имеет IP-адреса и ищет доступный DHCP-сервер в сети. Так как клиент пока не знает адрес сервера, сообщение передаётся широковещательно.

   **DHCP Offer** — это ответ DHCP-сервера на запрос клиента. В этом сообщении сервер предлагает клиенту IP-адрес и другие параметры конфигурации, например маску подсети, шлюз и DNS-сервер.

   **DHCP Request** — это сообщение клиента, в котором он подтверждает, что хочет использовать предложенные параметры. Если в сети находится несколько DHCP-серверов, клиент выбирает одно из предложений и отправляет запрос на использование выбранного адреса.

   **DHCP ACK** — это подтверждение от DHCP-сервера. После получения этого сообщения клиент окончательно принимает предложенный IP-адрес и начинает использовать его в сети.

   Кроме основных сообщений, в DHCP используются и другие типы сообщений. **DHCP NAK** применяется, если сервер отклоняет запрос клиента, например когда адрес больше недоступен. **DHCP Decline** отправляется клиентом, если он обнаружил, что предложенный адрес уже используется другим устройством. **DHCP Release** используется, когда клиент освобождает адрес и сообщает серверу, что больше не будет его использовать. **DHCP Inform** применяется в случаях, когда устройство уже имеет IP-адрес, но хочет получить от DHCP-сервера дополнительные параметры конфигурации.

3. Какие параметры могут быть переданы в сообщениях DHCP?

   В DHCP-сообщениях могут передаваться разные параметры, необходимые для полноценной работы устройства в IP-сети. Главным параметром является **IP-адрес**, который клиент получает из DHCP-пула. Вместе с ним обычно передаётся **маска подсети**, определяющая границы локальной сети.

   Также DHCP-сервер может передать адрес **шлюза по умолчанию**. Этот параметр нужен устройству для отправки пакетов в другие подсети. Например, если компьютер обращается к серверу из другой сети, он передаёт пакет через шлюз, которым обычно является интерфейс маршрутизатора.

   Важным параметром является адрес **DNS-сервера**. Благодаря ему клиент может обращаться к узлам по доменным именам, а не только по IP-адресам. Например, вместо ввода адреса **10.128.0.2** пользователь может обратиться к серверу по имени **[www.donskaya.rudn.ru](http://www.donskaya.rudn.ru)**, если соответствующая DNS-запись создана на DNS-сервере.

   DHCP также может передавать **доменное имя**, **время аренды адреса**, параметры продления аренды, адрес самого DHCP-сервера, широковещательный адрес сети, адреса NTP-серверов для синхронизации времени, параметры загрузочного сервера, адрес TFTP-сервера и другие служебные параметры.

   Таким образом, DHCP передаёт не только IP-адрес, но и полный набор сетевых настроек, который позволяет устройству сразу начать работу в локальной сети и взаимодействовать с другими подсетями.

4. Что такое DNS?

   **DNS** — это система доменных имён, которая используется для сопоставления удобных человеку доменных имён с IP-адресами сетевых узлов. Компьютеры и маршрутизаторы передают данные по IP-адресам, однако пользователям удобнее работать с именами, например **[www.donskaya.rudn.ru](http://www.donskaya.rudn.ru)**, а не с числовым адресом вида **10.128.0.2**.

   DNS выполняет функцию распределённого справочника. Когда пользователь обращается к сайту или серверу по имени, устройство отправляет запрос к DNS-серверу. DNS-сервер ищет соответствующую запись и возвращает IP-адрес, по которому находится нужный узел. После этого клиент уже может отправлять сетевые пакеты на полученный IP-адрес.

   В локальных сетях DNS часто используется для обращения к внутренним серверам организации. Например, можно создать записи для web-сервера, почтового сервера, файлового сервера и самого DNS-сервера. Это упрощает работу пользователей и администраторов, так как вместо запоминания IP-адресов используются понятные доменные имена.

   DNS также повышает гибкость администрирования. Если сервер был перенесён на другой IP-адрес, достаточно изменить DNS-запись. Пользователи продолжат обращаться к тому же доменному имени, а система будет направлять их на новый адрес.

5. Какие типы записи описания ресурсов есть в DNS и для чего они используются?

   Записи описания ресурсов в DNS называются **resource records**. Они определяют, какие данные связаны с конкретным доменным именем. В зависимости от назначения используются разные типы DNS-записей.

   **A Record** — это запись, которая сопоставляет доменное имя с IPv4-адресом. Например, запись **[www.donskaya.rudn.ru](http://www.donskaya.rudn.ru) — 10.128.0.2** означает, что web-сервер с данным именем доступен по IPv4-адресу **10.128.0.2**. Именно такие записи использовались при настройке DNS-сервера в лабораторной работе.

   **AAAA Record** выполняет похожую функцию, но используется для IPv6-адресов. Она связывает доменное имя не с IPv4-адресом, а с IPv6-адресом.

   **CNAME Record** задаёт псевдоним для другого доменного имени. Например, имя **[www.example.ru](http://www.example.ru)** может быть псевдонимом для **server1.example.ru**. Такая запись удобна, когда одному серверу нужно назначить несколько имён.

   **MX Record** указывает почтовые серверы, которые принимают электронную почту для домена. Например, если для домена настроена MX-запись, почтовые системы понимают, на какой сервер нужно доставлять письма.

   **NS Record** указывает DNS-серверы, которые являются ответственными за доменную зону. Эти записи позволяют определить, какие серверы хранят информацию о конкретном домене.

   **SOA Record** содержит служебную информацию о DNS-зоне: основной DNS-сервер зоны, адрес администратора, серийный номер зоны и параметры обновления. Эта запись является обязательной для зоны DNS.

   **PTR Record** используется для обратного разрешения имён. Если обычная A-запись преобразует доменное имя в IP-адрес, то PTR-запись позволяет по IP-адресу определить доменное имя. Такие записи часто применяются в диагностике сети и при проверке почтовых серверов.

   **TXT Record** хранит произвольную текстовую информацию. На практике такие записи часто используют для подтверждения владения доменом, настройки SPF, DKIM и DMARC для защиты электронной почты от подделки.

   **SRV Record** указывает расположение определённой службы в сети. В ней можно задать имя службы, протокол, порт и сервер, который предоставляет эту службу. Такие записи применяются, например, в корпоративных службах каталогов и системах IP-телефонии.

   **CAA Record** определяет, какие центры сертификации имеют право выпускать SSL/TLS-сертификаты для домена. Эта запись помогает повысить безопасность домена и снизить риск выпуска несанкционированных сертификатов.
