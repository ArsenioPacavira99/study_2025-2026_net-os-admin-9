# Контрольные вопросы

1. В каких случаях следует использовать статическую маршрутизацию? Приведите примеры.

   **Статическая маршрутизация** — это способ маршрутизации, при котором маршруты до удалённых сетей задаются администратором вручную. В отличие от динамической маршрутизации, маршрутизатор не обменивается маршрутной информацией с другими устройствами и не перестраивает таблицу маршрутизации автоматически при изменении топологии.

   Статическую маршрутизацию следует использовать в небольших или предсказуемых сетях, где количество маршрутов невелико, а структура соединений редко изменяется. В таких условиях ручная настройка маршрутов проще, чем внедрение динамических протоколов маршрутизации.

   Например, статическую маршрутизацию удобно применять при соединении двух офисов организации через выделенный канал. Если у основной площадки есть подсеть **10.128.0.0/24**, а у филиала — **10.130.0.0/24**, на маршрутизаторах можно вручную прописать маршруты до удалённых сетей через адрес соседнего маршрутизатора.

   Также статические маршруты применяются для настройки маршрута по умолчанию. Например, локальный маршрутизатор организации может отправлять весь неизвестный трафик на маршрутизатор провайдера с помощью команды вида:

   ```text
   ip route 0.0.0.0 0.0.0.0 198.51.100.1
   ```

Статическая маршрутизация также подходит для резервных маршрутов. В этом случае можно настроить статический маршрут с увеличенной административной дистанцией. Он не будет использоваться при наличии основного маршрута, но станет активным, если основной путь окажется недоступен.

Ещё один пример — маршрутизация в учебных лабораторных работах. В Packet Tracer статические маршруты часто используют для демонстрации принципов передачи пакетов между подсетями, поскольку администратор явно указывает, через какой маршрутизатор должна быть доступна каждая сеть.

Основные случаи применения статической маршрутизации:

* небольшие сети с простой топологией;
* соединение нескольких филиалов;
* настройка маршрута по умолчанию в сторону провайдера;
* резервный маршрут на случай отказа основного канала;
* изолированные сегменты сети, где не требуется динамический обмен маршрутами;
* учебные и демонстрационные топологии.

Преимущество статической маршрутизации состоит в простоте и предсказуемости. Администратор точно знает, какие маршруты используются и через какие интерфейсы передаётся трафик. Однако при большом количестве сетей такой способ становится неудобным, потому что каждый маршрут нужно добавлять и изменять вручную.

2. Укажите основные принципы статической маршрутизации между VLANs.

   **Маршрутизация между VLAN** используется в тех случаях, когда устройства находятся в разных виртуальных локальных сетях и должны обмениваться данными между собой. VLAN разделяют сеть на отдельные логические сегменты, поэтому устройства из разных VLAN не могут взаимодействовать напрямую только через коммутатор второго уровня. Для передачи трафика между VLAN требуется устройство третьего уровня: маршрутизатор или L3-коммутатор.

   Основной принцип заключается в том, что для каждой VLAN должна быть создана отдельная IP-подсеть. Например, VLAN **201** может использовать сеть **10.129.0.0/24**, а VLAN **202** — сеть **10.129.1.0/24**. Устройства внутри каждой VLAN получают IP-адреса из своей подсети, а в качестве шлюза по умолчанию используют IP-адрес интерфейса маршрутизатора или L3-коммутатора, связанного с этой VLAN.

   Если используется схема **router-on-a-stick**, то маршрутизатор подключается к коммутатору одним физическим интерфейсом, а на этом интерфейсе создаются логические подинтерфейсы. Каждый подинтерфейс соответствует отдельной VLAN и получает свой IP-адрес. На коммутаторе порт, ведущий к маршрутизатору, настраивается как **trunk**, чтобы по нему могли передаваться кадры разных VLAN с тегами **802.1Q**.

   Пример настройки подинтерфейсов на маршрутизаторе:

   ```text
   interface FastEthernet0/0.201
    encapsulation dot1Q 201
    ip address 10.129.0.1 255.255.255.0

   interface FastEthernet0/0.202
    encapsulation dot1Q 202
    ip address 10.129.1.1 255.255.255.0
   ```

   В этом примере подинтерфейс **FastEthernet0/0.201** обслуживает VLAN **201**, а подинтерфейс **FastEthernet0/0.202** обслуживает VLAN **202**. Адреса **10.129.0.1** и **10.129.1.1** могут использоваться как шлюзы по умолчанию для устройств соответствующих VLAN.

   На коммутаторе необходимо создать VLAN и назначить пользовательские порты в нужные VLAN. Порт, соединяющий коммутатор с маршрутизатором, должен работать в транковом режиме:

   ```text
   vlan 201
    name USERS_Q42

   vlan 202
    name MGMT_Q42

   interface FastEthernet0/24
    switchport mode trunk
   ```

   Если маршрутизация выполняется на L3-коммутаторе, то для каждой VLAN создаётся виртуальный интерфейс **SVI**. Такой интерфейс получает IP-адрес и становится шлюзом для устройств своей VLAN. Дополнительно на L3-коммутаторе включается маршрутизация командой **ip routing**.

   Пример настройки SVI:

   ```text
   ip routing

   interface vlan 201
    ip address 10.129.0.1 255.255.255.0
    no shutdown

   interface vlan 202
    ip address 10.129.1.1 255.255.255.0
    no shutdown
   ```

   При статической маршрутизации между VLAN важно не только настроить шлюзы для локальных VLAN, но и прописать маршруты до удалённых сетей. Если маршрутизатор 42-го квартала должен передавать трафик в сторону центральной площадки или филиала, на нём указываются статические маршруты через соседний маршрутизатор.

   Например:

   ```text
   ip route 10.128.0.0 255.255.255.0 10.128.255.1
   ip route 10.130.0.0 255.255.255.0 10.128.255.1
   ```

   Основные принципы статической маршрутизации между VLANs:

   * каждая VLAN должна относиться к отдельной IP-подсети;
   * для каждой VLAN должен быть настроен шлюз по умолчанию;
   * между коммутатором и маршрутизатором должен быть настроен trunk, если используется router-on-a-stick;
   * на маршрутизаторе должны быть созданы подинтерфейсы с инкапсуляцией **802.1Q**;
   * при использовании L3-коммутатора для VLAN создаются интерфейсы **SVI**;
   * на конечных устройствах должен быть правильно указан IP-адрес шлюза;
   * для удалённых сетей должны быть добавлены статические маршруты;
   * маршруты должны быть прописаны в обе стороны, иначе ответы от удалённых узлов не смогут вернуться обратно.
