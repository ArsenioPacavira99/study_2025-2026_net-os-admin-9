# Контрольные вопросы

1. Как задать действие правила для конкретного протокола?

   Действие правила для конкретного протокола задаётся при создании расширенного списка контроля доступа. В правиле указывается действие **permit** или **deny**, затем протокол, к которому это правило должно применяться: **ip**, **tcp**, **udp**, **icmp** и другие.

   Общий вид команды для расширенного ACL можно записать следующим образом:

   `permit|deny protocol source destination parameters`

   Например, чтобы разрешить HTTP-доступ к web-серверу с адресом **10.128.0.2**, используется правило:

   `permit tcp any host 10.128.0.2 eq 80`

   В этом правиле действие **permit** означает разрешение трафика, протокол **tcp** указывает, что правило применяется только к TCP-пакетам, адрес **10.128.0.2** задаёт конкретный сервер назначения, а параметр **eq 80** ограничивает доступ только портом 80, то есть протоколом HTTP.

   Для разрешения ICMP-сообщений можно использовать правило:

   `permit icmp any any`

   В этом случае правило применяется именно к ICMP-трафику, который используется, например, командой **ping** для проверки доступности узлов сети.

2. Как задать действие правила сразу для нескольких портов?

   Действие правила сразу для нескольких портов можно задать с помощью оператора **range**, если нужные порты идут подряд. Этот оператор позволяет указать диапазон портов, к которым будет применяться одно правило.

   Например, для разрешения доступа к FTP-серверу могут использоваться порты **20** и **21**. В этом случае можно задать правило:

   `permit tcp any host 10.128.0.3 range 20 21`

   Такое правило разрешает TCP-трафик к серверу **10.128.0.3** сразу для диапазона портов от **20** до **21**.

   Если порты не образуют непрерывный диапазон, то обычно создаётся несколько отдельных правил. Например, для почтового сервера SMTP использует порт **25**, а POP3 — порт **110**, поэтому правила можно задать отдельно:

   `permit tcp any host 10.128.0.4 eq 25`

   `permit tcp any host 10.128.0.4 eq 110`

   Такой подход удобен, потому что каждое правило явно показывает, какой именно сервис разрешён. Это упрощает проверку и дальнейшее редактирование списка контроля доступа.

3. Как узнать номер правила в списке прав доступа?

   Номер правила в списке прав доступа можно узнать с помощью команды просмотра ACL:

   `show access-lists`

   Эта команда выводит все созданные списки контроля доступа и правила внутри них. В именованных расширенных ACL перед каждым правилом отображается его порядковый номер. Например:

   `10 permit tcp any host 10.128.0.2 eq www`

   `20 permit tcp host 10.128.6.200 host 10.128.0.2 range 20 ftp`

   `30 permit tcp host 10.128.6.200 host 10.128.0.2 eq telnet`

   Числа **10**, **20**, **30** являются номерами правил. Они определяют порядок применения условий внутри ACL. Чем меньше номер, тем раньше проверяется правило.

   Также можно использовать команду:

   `show running-config`

   В текущей конфигурации отображаются созданные списки доступа и команды, которыми они были настроены. Однако для просмотра именно номеров правил удобнее использовать команду **show access-lists**.

4. Каким образом можно изменить порядок применения правил в списке контроля доступа?

   Порядок применения правил в списке контроля доступа определяется их расположением в ACL. Маршрутизатор проверяет правила сверху вниз: сначала первое правило, затем второе, третье и так далее. Как только пакет совпадает с одним из правил, дальнейшая проверка для него прекращается.

   Изменить порядок правил можно с помощью номеров строк в именованном ACL. Для этого нужно перейти в режим настройки нужного списка доступа:

   `ip access-list extended servers-out`

   Затем можно добавить новое правило с нужным номером. Например:

   `15 permit tcp any host 10.128.0.2 eq 443`

   Если в списке уже есть правила с номерами **10** и **20**, то правило с номером **15** будет помещено между ними. Это позволяет изменить порядок проверки без полного удаления списка.

   Если правило было добавлено неправильно, его можно удалить по номеру:

   `no 15`

   После этого можно создать новое правило с другим номером или другими параметрами.

   Важно учитывать, что в конце каждого списка контроля доступа существует неявное правило:

   `deny ip any any`

   Оно не отображается в конфигурации, но автоматически запрещает весь трафик, который не подошёл ни под одно разрешающее правило. Поэтому более частные разрешающие правила следует размещать выше общих запрещающих правил, иначе нужный трафик может быть заблокирован раньше, чем маршрутизатор дойдёт до разрешения.
