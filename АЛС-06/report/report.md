# Цель работы

Настроить статическую маршрутизацию VLAN в сети.

# Ход выполнения

В логической области проекта Packet Tracer была продолжена настройка локальной сети с несколькими VLAN. В рабочем пространстве был размещён маршрутизатор **Cisco 2811**, которому было задано имя **msk-donskaya-arsenio-gw-1**. Маршрутизатор был подключён к порту **FastEthernet0/24** коммутатора **msk-donskaya-arsenio-sw-1** в соответствии с таблицей портов. Данное подключение используется для организации маршрутизации между VLAN по схеме **router-on-a-stick**, при которой несколько VLAN передаются между коммутатором и маршрутизатором по одному физическому каналу.

![Размещение маршрутизатора Cisco 2811 в логической области проекта](Screenshot_1.png){ #fig:001 width=75% }

Далее была выполнена первоначальная настройка маршрутизатора. Для этого был открыт интерфейс **CLI**, после чего был выполнен переход в привилегированный режим и режим глобальной конфигурации. На маршрутизаторе было задано имя **msk-donskaya-arsenio-gw-1**, настроены пароли для консольного и удалённого доступа, а также включено шифрование паролей.

Для настройки удалённого подключения был задан домен **donskaya.rudn.edu**, создан локальный пользователь **admin** с паролем **cisco**, после чего были сгенерированы RSA-ключи. На линиях **VTY 0 4** был разрешён вход по **SSH**. Затем был включён физический интерфейс **FastEthernet0/0**, через который маршрутизатор соединяется с коммутатором.

В ходе первоначальной настройки были использованы команды перехода в режим конфигурации, задания имени устройства, настройки пароля на консоль, включения локального пользователя, задания доменного имени, генерации RSA-ключей, настройки линий VTY и включения интерфейса **FastEthernet0/0**. После выполнения команды **no shutdown** в CLI появилось сообщение о переходе интерфейса и протокола линии в состояние **up**, что подтверждает успешное включение соединения между маршрутизатором и коммутатором.

# Контрольные вопросы

1. Охарактеризуйте стандарт IEEE 802.1Q.

   **IEEE 802.1Q** — это стандарт канального уровня, который описывает способ передачи кадров Ethernet с принадлежностью к определённой виртуальной локальной сети **VLAN**. Он используется для логического разделения одной физической сети на несколько независимых широковещательных доменов.

   Основная задача стандарта **IEEE 802.1Q** заключается в том, чтобы коммутаторы, маршрутизаторы и другие сетевые устройства могли определять, к какой VLAN относится передаваемый Ethernet-кадр. Для этого в кадр добавляется специальная метка — **VLAN-тег**. Благодаря этому один физический канал между сетевыми устройствами может одновременно передавать трафик нескольких VLAN.

   Стандарт особенно важен при настройке **trunk-соединений**. Trunk-порт передаёт кадры разных VLAN между коммутаторами или между коммутатором и маршрутизатором. В обычном access-порту конечное устройство работает только в одной VLAN, поэтому кадры чаще всего передаются без тега. На trunk-порту, наоборот, кадры получают дополнительную служебную информацию, по которой принимающее устройство определяет номер VLAN.

   В лабораторной работе стандарт **IEEE 802.1Q** использовался при настройке маршрутизации между VLAN по схеме **router-on-a-stick**. На коммутаторе порт, соединённый с маршрутизатором, был настроен как trunk-порт, а на маршрутизаторе были созданы подинтерфейсы **FastEthernet0/0.2**, **FastEthernet0/0.3**, **FastEthernet0/0.101**, **FastEthernet0/0.102**, **FastEthernet0/0.103** и **FastEthernet0/0.104**. Каждый подинтерфейс был связан с отдельным номером VLAN с помощью инкапсуляции **dot1Q**.

   Использование **IEEE 802.1Q** позволяет передавать трафик нескольких логических сетей через один физический интерфейс. Это снижает количество необходимых кабелей и портов, упрощает структуру сети и позволяет централизованно выполнять маршрутизацию между VLAN.

   Кроме разделения трафика по VLAN, стандарт также поддерживает передачу информации о приоритете кадра. Это используется для механизмов качества обслуживания **QoS**, когда определённые типы трафика, например голосовой или служебный, могут получать более высокий приоритет при обработке.

2. Опишите формат кадра IEEE 802.1Q.

   Кадр **IEEE 802.1Q** представляет собой обычный Ethernet-кадр, в который добавлено дополнительное поле длиной **4 байта**. Это поле называется **802.1Q tag** или **VLAN-tag**. Оно вставляется между полем **Source MAC Address** и полем **Type/Length** исходного Ethernet-кадра.

   Обычный Ethernet-кадр содержит MAC-адрес получателя, MAC-адрес отправителя, поле типа или длины, данные и контрольную сумму кадра. При использовании **IEEE 802.1Q** между MAC-адресом отправителя и полем типа добавляется тег, который указывает принадлежность кадра к VLAN.

   Формат кадра **IEEE 802.1Q** включает следующие основные поля:

   **Destination MAC Address** — MAC-адрес получателя кадра. Это поле занимает **6 байт** и указывает устройство, которому предназначен кадр в пределах канального сегмента сети.

   **Source MAC Address** — MAC-адрес отправителя кадра. Это поле также занимает **6 байт** и показывает, какое устройство сформировало данный Ethernet-кадр.

   **TPID (Tag Protocol Identifier)** — идентификатор протокола тега. Поле занимает **2 байта**. Для кадров **IEEE 802.1Q** обычно используется значение **0x8100**. По этому значению сетевое устройство понимает, что кадр содержит VLAN-тег.

   **TCI (Tag Control Information)** — управляющая информация тега. Поле занимает **2 байта** и содержит сведения о приоритете кадра и номере VLAN.

   Поле **TCI** делится на несколько частей:

   **PCP (Priority Code Point)** — поле приоритета длиной **3 бита**. Оно используется для указания класса обслуживания кадра. Значения приоритета могут применяться при настройке QoS.

   **DEI (Drop Eligible Indicator)** — поле длиной **1 бит**. Оно показывает, может ли кадр быть отброшен при перегрузке сети. Ранее это поле называлось **CFI**.

   **VID (VLAN Identifier)** — идентификатор VLAN длиной **12 бит**. Именно это поле определяет номер VLAN, к которой относится кадр. За счёт 12 бит можно закодировать 4096 значений, однако на практике для пользовательских VLAN обычно применяются номера от **1** до **4094**, так как отдельные значения зарезервированы.

   **Type/Length** — поле типа или длины, которое занимает **2 байта**. Оно указывает, какой протокол верхнего уровня передаётся внутри кадра. Например, значение **0x0800** соответствует IPv4.

   **Data** — поле данных переменной длины. В нём передаются данные протоколов верхних уровней, например IP-пакет, внутри которого может находиться ICMP-сообщение.

   **FCS (Frame Check Sequence)** — контрольная последовательность кадра длиной **4 байта**. Она используется для проверки целостности кадра при передаче по сети.

   Добавление VLAN-тега увеличивает размер Ethernet-кадра на **4 байта**. Поэтому максимальный размер кадра с тегом **IEEE 802.1Q** составляет не **1518 байт**, как у обычного Ethernet-кадра, а **1522 байта**.

   В режиме симуляции Packet Tracer это можно увидеть при анализе PDU. На trunk-участке между коммутатором и маршрутизатором кадр отображается как **Ethernet 802.1Q**. В его структуре присутствуют поля **TPID: 0x8100** и **TCI**, содержащие информацию о VLAN. После выхода кадра на access-порт конечного устройства VLAN-тег удаляется, и кадр снова отображается как обычный **Ethernet II**.
